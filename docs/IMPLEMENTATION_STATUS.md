Pre-M13 S1 — match-pattern correctness (closed 2026-08-12). Four behaviour changes land in lock-step in the C bootstrap (`src/semantic.c`, `src/emit_c.c`) and the self-hosted compiler (`src/tiq/semantic.tiq`, `src/tiq/emit_c.tiq`):

  1. **Irrefutable-last rule**: a bare binding pattern (e.g. `v`) is also irrefutable — it matches every value — and must be the final arm, just like `_`. Earlier irrefutable arms (wildcard or bare binding) make every later arm unreachable and are rejected with E07 ("irrefutable pattern must be the last arm"). The pre-existing wildcard-required rule is subsumed; the legacy "match must have a wildcard arm" diagnostic remains so programs that use only bare bindings as their last arm still get a clear pointer to add `_ => ...`.
  2. **Recursive constructor lowering**: `some(p)`, `ok(p)`, `err(p)` now test the payload pattern `p` rather than only the outer tag. The C bootstrap's `emit_match` + `emit_pat_cond` + `emit_pat_binds` walk the pattern tree, threading the typed accessor path (`_t.value` for `some`/`ok`, `_t.error` for `err`) and the corresponding inner type; nested constructors (`some(some(v))`, `ok(0)`) test the full payload structure. Nested Option/Result constructors that depend on `Option<T> = int64_t` storage still hit the M13.1-P4/S4 limitation at the assignment boundary; recursive match lowering is correct against the C types it is given.
  3. **Byte equality for string patterns**: literal patterns of type `str` use `tiq_str_eq(_t, "literal")` instead of C pointer equality. Heap-allocated strings (the result of `str_cat`, `fs_read`, `net_fetch`, `json_get`, etc.) now compare correctly across allocations — the previous emit silently miscompared pointer addresses and clang's `-Wstring-compare` warned at every match on a heap string. Integer, float, bool, enum-variant patterns still use `==` because it is sound for those kinds.
  4. **Enum scrutinee type check**: an enum variant pattern (`Color.Red`) against a non-integer scrutinee is unreachable and rejected with E09 ("enum variant pattern requires integer scrutinee, found str") before code generation, with the located diagnostic printed through `type_display`.

Collision-free internal names for the scrutinee / result temporaries (the `tiq_m_t_<N>` / `tiq_m_r_<N>` design in S1) is documented as deferred: the C bootstrap keeps the pre-existing `_t` / `_r` shape so the self-hosted compiler and the bootstrap emit byte-equal C for match expressions, keeping `tests/selfhost_emit_c.sh` at 52 byte-identical core cases. The `__extension__({ ... })` statement expression is likewise retained for now — removing it requires AST lowering across every expression-context call site (AST_CALL, AST_BINDING, AST_CONDITIONAL, ...) and is left for a follow-up slice. Both items are tracked in the Pre-M13 gate as still-open sub-items.

Evidence: `tests/semantic.sh` adds four new goldens — `match_binding_not_last` and `match_two_bindings` (irrefutable-not-last), `match_enum_on_string_scrutinee` (enum scrutinee type check), `match_str_pattern_on_int_scrutinee` (str pattern with int scrutinee fails closed), and `typed_match_nested_ctor_literal` (typed AST golden pinning `PAT_CTOR some` with `PAT_INT 0`). `tests/smoke.sh` adds `match_str_eq` (byte-equality verified for both literal-strings and `str_cat`-produced heap strings, asserting the latter match `1` and `2` correctly), `match_nested_some` (single-layer `some(0)` literal-payload recursion pinned), and `match_no_collision` (two nested matches in one translation unit exercise the per-emission counter for nested scratch and result bindings). `tests/selfhost_semantic.sh` corpus still byte-compares 131 error + 58 construct cases; `tests/selfhost_emit_c.sh` 52 core cases + fail-closed preflight + compiler dogfood identity all pass byte-identically because the bootstrap and the self-hosted compiler share the `_t` / `_r` emission shape. M17.1 — Pattern matching as a first-class syntactic category (closed 2026-08-11). Issue #6 — bindings never shadow; `<-` resolves mutable-first, `=` never redefines (closed 2026-08-08). Previously `name <- expr` re-declared the name in the current scope even when a binding already existed wherever, and `name = expr` let a later definition shadow an outer binding: both failed silently as scope shadowing, contradicting fail-closed and creating ambiguous programs (LANGUAGE_SPEC §6 now mandates it). Now `<-` resolves the name outward and applies exactly one outcome — reassign the nearest mutable binding; error E11 on an immutable (or nearest-any) collision; declare a new mutable binding only when no binding exists anywhere — so nested-block reassignment mutates the single outer binding and the duplicate-declaration warning that fired for `x = 1; x = 2` is gone (now E11). `=` definitions are likewise never allowed to redefine a name that exists in any enclosing scope, and a same-scope `=`/`=` or `<-`/`=` redefinition is E11. Implemented in lock-step in the C bootstrap (`src/semantic.c` AST_BINDING/identifier scope walk) and the self-hosted compiler (`src/tiq/semantic.tiq` BINDING case). Diagnostics carry source location and are tested. Tests: `tests/semantic.sh` (`arrow_immutable_same_scope`, `arrow_immutable_outer_scope`, `redefine_immutable_same_scope`, `redefine_mutable_same_scope`), `tests/run.sh` (`arrow_reassign`, `arrow_deep_reassign`), and corpus updates in `tests/selfhost_semantic.sh` (`e11_arrow_immutable_same_scope`, `e11_arrow_immutable_outer_scope`, `e11_redefine_immutable`, `e11_redefine_mutable`, `e11_redefine_block_shadow`) plus positive `case_run` pins in `tests/selfhost_emit_c.sh` (`arrow_decl_reassign`, `arrow_nested_reassign`, `arrow_deep_reassign`, `arrow_fn_nested_reassign`); `selfhost_semantic.sh` now byte-compares 131 error + 58 construct cases and `selfhost_emit_c.sh` runs 52 executable core cases. Spec: LANGUAGE_SPEC §6.

Issue #5 Finding 3 — `none` is now a real reserved literal/token (done 2026-08-07). Spec/grammar updated (LANGUAGE_SPEC §4 literal list + §15.1 note; GRAMMAR `literal`). Tests added: `tests/lexer.sh` (`none_keyword`, `none_value`, `none_near_miss`), `tests/parser.sh` (`none_literal`), `tests/semantic.sh` (`none_reserved_lhs`, `none_literal_not_callable`), and `tests/selfhost_semantic.sh` corpus `none_literal_call`. Diagnostics carry source location and are tested.

- M9 (active): M9.1 borrowed parameters implemented 2026-07-29 — `&T` / `&mut T` parameter annotations, `&x` / `&mut x` call arguments, auto-deref of reference parameters in callee bodies, mutation through `&mut` (emitted as `const T *` / `T *`). Call-site checking (E23): borrow spelling must match the parameter, `&mut` requires a mutable binding, reference parameters cannot be re-borrowed or assigned through when shared, per-call aliasing (many shared, at most one `&mut`, never mixed), borrow of a moved value is E18. Borrows anywhere else still fail closed ("borrow is only valid as an argument to a reference parameter", E07). Lifetimes are structurally valid in this slice: borrows cannot be stored or returned. M9.2-A implemented 2026-07-29 — scope-bound destruction of owned builtin strings (LANGUAGE_SPEC §16.4): immutable bindings initialized from a direct `fs_read`/`json_encode_str`/`json_get`/`json_arr_get`/`net_fetch` call are freed at scope end, reverse declaration order, after defers; builtins always return fresh heap storage with a deterministic out-of-memory abort. Mutable bindings, function bodies, temporaries, and early-exit paths are not yet destroyed. M9.2-B implemented 2026-07-29 — `break` and `skip` destroy the owned strings of every scope they exit (innermost first, through the enclosing loop body) before transferring control; `proc_exit` still bypasses destruction. M9.2-C implemented 2026-07-29 — scalar-result functions (integers, floats, `bool`) destroy their body's owned strings after the result is computed into a temporary; pointer-carrying result types (`str`, composites) still leak instead of dangling. M9.2-D implemented 2026-07-29 — mutable (`<-`) bindings own their strings under a conservative escape test (initializer and every reassignment are direct owned-builtin calls; the name otherwise appears only as a builtin argument): qualifying owners free the previous string on reassignment and are freed at scope end; disqualified mutables leak, never dangle. M9.2-E implemented 2026-07-29 — a statement-level `proc_exit(code)` frees the owned strings of every lexically enclosing scope (innermost first, up to the current function body or program scope) before terminating; the exit code is computed before destruction; embedded `proc_exit` uses still bypass destruction. M9.2-F implemented 2026-07-29 — unbound owned-builtin temporaries in unconditionally evaluated positions of simple statements (the bare statement expression, or a direct argument to a standard-library builtin nested through such builtins) are hoisted into hidden bindings and freed at the end of the containing statement; temporaries in conditional positions, match arms, loop headers, and user-function arguments still leak, never dangle. M9.2-G implemented 2026-07-29 — a `str`-result function whose final expression is a string literal or a direct owned-builtin call (storage provably distinct from every owner) destroys its body's owners after the result is computed; composite and conditional results may alias an owner and still leak. M9.2-H implemented 2026-07-29 — a `str`-result function whose final expression is a bare identifier naming a body owner transfers that owner to the caller: every other owner is freed after the result is computed; alias-identifier results still free nothing. M9.2-I implemented 2026-07-29 — top-level functions are classified fresh-result before emission (a `str` result expression that is a direct heap-builtin call or a bare identifier naming a body owner), and a binding initialized from a direct call to one owns the returned string and is destroyed at scope end; string-literal results stay static and unowned, and mutable reassignment still requires a builtin call. M9.2-J implemented 2026-07-29 — an unbound fresh-result call in an unconditionally evaluated position of a simple statement is hoisted into a hidden binding and freed at statement end, and the arguments of a fresh-result call are such positions too (its result cannot alias them); calls to functions that are not fresh-result are still not hoist positions, so those temporaries leak, never dangle. M9.2-K implemented 2026-07-29 — a binding whose initializer is a conditional expression owns the result when both branches are owning expressions (heap-builtin calls, fresh-result calls, or nested conditionals); also fixes AST_CONDITIONAL semantic type propagation (unified branch type instead of TYPE_UNKNOWN). M9.2-L implemented 2026-07-29 — a conditional expression whose branches are both owning expressions, appearing as a direct argument to a standard-library builtin or to a fresh-result function, or as the bare statement expression, is hoisted into a hidden binding and freed at statement end; conditionals with non-owning branches still leak, never dangle. No allocator interfaces or `Shared<T>`.

## Known bootstrap limitations

- Temporary-file creation and host compiler execution currently use POSIX APIs; non-POSIX platforms need an equivalent documented process abstraction.
- The implementation is a proof of the compilation path, not a production compiler.
- Block bodies produce double braces in generated C (cosmetic, valid C11).
- Formatter is conservative; some stylistic variations may not be normalized.
